# Architecture

Playwright Test owns browser fixtures, isolation, assertions, and debugging. Bun test owns API tests using native fetch. No additional HTTP client or custom runner is needed.

`bunfig.toml` limits default Bun discovery to `tests/api/specs`; API files use `.test.ts`. Playwright explicitly scans `tests/e2e/specs/**/*.spec.ts`. CLI overrides should not broaden these roots. Scripts use Bun to execute Playwright.

Browser configuration validates only PH_WEB_BASE_URL. API support validates the HTTPS endpoint separately. Only the environment-auth branch calls requiredToken(); missing credentials fail before fetch. Each request builds fresh headers; omitted and fixed-invalid modes never consult the real credential.

Browser concurrency is one worker, with zero retries locally and in CI so failures remain visible. Test timeout is 30 seconds, assertions/actions 10 seconds, navigation 30 seconds, and suite limit five minutes. API runner timeout is 15 seconds and concurrency cap one; the specs run sequentially. Each fetch, including body consumption, has a six-second abort deadline; two sequential requests fit within the test timeout.

Each browser test receives the built-in isolated page and context. A global setup opens the homepage once with a clean Chromium instance. An access challenge fails the run before any scenario executes. An ordinary successful response leaves product assertions to the specs. Global setup uses the resolved single Chromium project's launch mode and desktop context settings. A blocked navigation writes test-results/access-preflight.json with the time, origin, HTTP status, browser version and classification. It excludes headers, URLs with query strings and page content. Global setup has its own artifact handling. Screenshot and trace retention applies to scenario failures. API cases independently obtain suitable public records, avoid mutable rankings/counts, and avoid execution-order dependencies. No writes, shared login state, or hardcoded daily product names are planned.

tests/api/support/client.ts returns HTTP status and an unknown JSON body, including on 401. Redirects are rejected and there are no retries. Timeout, transport and non-JSON failures report controlled messages. contracts.ts checks envelopes and narrows fields at runtime; the specs test OAuth error properties separately from GraphQL messages and extensions. Identity mismatch diagnostics compare the selected public field values. Headers and raw response bodies are excluded.

Small suite-specific helpers are sufficient. Page objects require demonstrated repetition. `shared/` is omitted until a utility serves both suites. The local workflow separates static, API and E2E jobs. Only a trusted main API step receives the Product Hunt secret. Failure uploads include preflight metadata and scenario screenshots for three days. Hosted validation is pending. Action versions and secret handling were checked against the maintainers' references. [Checkout](https://github.com/actions/checkout) · [Setup Bun](https://github.com/oven-sh/setup-bun) · [Artifact upload](https://github.com/actions/upload-artifact) · [GitHub secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets) listing.ts shares product discovery and detail navigation. Search helpers stay in the search spec. Product names, paths and generated empty queries belong to the test that uses them.

Failure screenshots and retained failure traces go in ignored `test-results/`. These may contain sensitive information: review/redact before sharing. Secrets, auth state, reports, dependencies, and artifacts are ignored. Ignore rules are preventive, not a substitute for inspecting staged files before a future commit.

Biome handles linting and formatting without ESLint/Prettier overlap. Dependencies are exact-pinned and Bun's lockfile is retained. Strict TypeScript checks our code; library declaration checking is skipped to keep checks focused. Chromium-only coverage keeps the 4–6 hour task manageable.
